# Drei durchgehende Szenarien

Diese Beispiele sind **rein erklärend**. Weder Konten noch laufende Server sind notwendig.

## Beispiel 1: Kleines Online-Werkzeug {#S1}

Eine Person betreibt eine einfache kostenpflichtige Website mit Benutzerkonten, Webanwendung, Schnittstelle und relationaler Datenbank. Die Grundidee soll zunächst auf einem einzelnen, ausreichend dimensionierten Host laufen können.

``` text
Nutzer → Weboberfläche → Anwendungsprozess → Datenbank
```

Zu erläutern: Sicherheit, Accounts, Backups, Updates, Bezahlung, Support und laufende Kosten.

## Beispiel 2: Derselbe Dienst bei höherer Nachfrage {#S2}

Der Dienst wird intensiv genutzt. Zuerst Engpässe messen, dann mögliche Maßnahmen vergleichen: Caching, mehrere Dienstinstanzen, Warteschlangen, Lesereplikate – Sharding erst, wenn überhaupt erforderlich.

``` text
                  ┌→ Instanz A ─┐
Nutzer → Verteiler               ├→ Datenhaltung
                  └→ Instanz B ─┘
```

Zu erläutern: Kosten und neue Fehlerquellen, geteilte Zustände, Konsistenz und Ausfallszenarien.

## Beispiel 3: KI-Jobs und später Geräte {#S3}

Aufträge gelangen über eine Schnittstelle in eine Warteschlange; spezialisierte Worker verarbeiten sie, legen Ergebnisse ab und melden Zustände zurück.

``` text
Nutzer → API → Warteschlange → KI-Worker → Ergebnisablage
                   │
                   └→ Status / Fehlerbehandlung
```

Zu erläutern: Doppelbearbeitung, Wiederholungsversuche, GPU-Kosten, Datenschutz, Ausfallbehandlung und – für Geräte – lokale Steuerung statt ausschließlicher Internetabhängigkeit.
